# Handoff: QURAL-SAIMAN — перенос на Next.js + Supabase с админкой

## Overview

Работающий сайт проката строительного инструмента в Шымкенте (каталог 88 позиций + раздел генераторов ДГУ) нужно перенести на Next.js с базой данных, чтобы владелец сам добавлял, редактировал и удалял инструменты через админку — без правки кода.

Сейчас каталог живёт в статическом файле `tools-data.js` (массив из 88 объектов). Задача — перевести эти данные в Postgres (Supabase), сделать публичные страницы серверно-рендеримыми из базы, и построить закрытый раздел `/admin`.

**Что НЕ меняется:** дизайн публичной части. Он готов, вылизан и одобрен — переносится один в один.

## About the Design Files

Файлы в этом пакете — **дизайн-референсы, сделанные в HTML**. Это не production-код, который нужно копировать целиком: это прототипы, точно показывающие нужный вид и поведение.

Задача — **воспроизвести эти макеты в Next.js**, используя его обычные подходы (App Router, React-компоненты, CSS Modules или Tailwind). Существующий `app.css` — точный источник значений (цвета, отступы, радиусы, размеры шрифтов); его можно перенести почти дословно, разбив по компонентам, либо конвертировать в Tailwind-конфиг по таблице токенов ниже.

## Fidelity

**High-fidelity.** Публичные страницы — финальный дизайн, работающий на реальных данных и реальных фото; воспроизводить пиксель в пиксель. `admin.html` — тоже hi-fi макет: цвета, размеры, состояния и тексты финальные, но данные в нём захардкожены и кнопки ничего не сохраняют.

## Схема базы

Полный SQL — в `schema.sql` этого пакета (создание таблиц, индексы, RLS-политики, триггеры `updated_at`, дефолтные скидки). Кратко:

- `families` — 5 групп категорий (Бетон и грунт, Резка и демонтаж, Шлифовка и отделка, Энергия и сварка, Высота/сад/уборка)
- `categories` — 20 категорий, у каждой `family_id`, `name`, `short` (для чипов), `icon` (имя lucide-иконки)
- `tools` — инструменты: `slug`, `category_id`, `name`, `spec`, `brand`, `power`, `price`, `deposit`, `price_note`, `photo_path`, `is_top`, `is_published`
- `generators` — ДГУ отдельной таблицей: ключевое поле `kw` (мощность), цена может быть `null` = «по запросу»
- `discount_tiers` — сетка скидок за длительную аренду (7 дней −10%, 30 дней −20%)
- `admins` — белый список `user_id`, на нём построены RLS-политики

**Наличия на складе в базе нет.** Остатки ведутся в 1С, интеграция не планируется. Сайт работает как меню: клиент смотрит позиции и цены, заявка уходит в WhatsApp, менеджер сверяет наличие сам. Единственный флаг видимости — `is_published`.

**Мультиязычность заложена, но не включена.** У всех текстовых полей есть парный `*_kz` (`name_kz`, `spec_kz`, `price_note_kz`). Пока они пустые. Фронт читает через хелпер `t(row, 'name', locale)`, который падает на русский, если казахского нет. Когда переводы появятся — включается роутинг `/[locale]/`, база менять не придётся.

### Миграция данных

`tools-data.js` (в пакете) — уже нормализованный источник: массивы `families`, `categories`, `tools`, `dgu`. Написать разовый seed-скрипт, который читает его и заливает в базу. Фото лежат в `assets/tools/<slug>.png` — загрузить в бакет `tools` тем же скриптом, `photo_path` = `tools/<slug>.png`.

## Админка `/admin`

Макет — `admin.html`. Один пользователь (владелец), вход по magic link на его email. Middleware закрывает всё под `/admin` для остальных.

### Разделы

1. **Инструменты** — список с поиском, фильтрами (категория, статус), сортировкой; создание/редактирование в правой панели (drawer); дублирование; удаление с подтверждением; переключатели «Показывать на сайте» и «Хит проката».
2. **Категории** — CRUD, привязка к семейству, выбор иконки, перетаскивание для порядка (`sort`).
3. **Генераторы ДГУ** — отдельный список; форма проще: мощность в кВт, цена или «по запросу».
4. **Цены и скидки** — редактирование сетки `discount_tiers`; массовое изменение цен в категории (напр. «+10% ко всем перфораторам»).
5. **Фото и медиа** — список файлов бакета, поиск позиций без фото.

После любой мутации — `revalidatePath()` на затронутые публичные роуты, чтобы сайт обновлялся сразу.

### Валидация формы

- `name` — обязательно, 2–120 символов.
- `slug` — обязательно, уникально, `^[a-z0-9-]+$`; предлагать транслитерацию из названия, но давать править.
- `category_id` — обязательно.
- `price` — целое > 0. Для ДГУ допустимо пусто = «по запросу».
- `spec` — до 90 символов (иначе ломает карточку каталога) — показывать счётчик.
- Фото — до 2 МБ, только PNG/JPEG/WebP; предупреждать, если меньше 800×800.
- Ошибки — красная граница поля `#C0392B` + подпись 11.5px/700 того же цвета под полем.

### Состояния

- **Загрузка списка**: скелетон — 6 строк таблицы, блоки `#F6F6F3`, пульсация `1.4s ease-in-out infinite`.
- **Сохранение**: кнопка блокируется, текст → «Сохраняем…», спиннер 15×15.
- **Успех**: тост внизу справа, фон `#1A1A1A`, текст `#fff`, радиус 12px, 13px/700, живёт 2.5 с.
- **Ошибка сети**: тост с фоном `#FDECEA`, текстом `#C0392B` и кнопкой «Повторить».
- **Пустой список**: по центру карточки — иконка 40×40 `#DEDED8`, заголовок 15px/800, подпись 13px `#6B6B66`, кнопка «Добавить инструмент».
- **Удаление**: модальное подтверждение с названием позиции; кнопка подтверждения красная.

## Порядок работ

1. `create-next-app` (TypeScript, App Router), перенос `app.css`, шрифтов и `assets/`.
2. Supabase: проект, `schema.sql`, бакет `tools`, первый вход владельца → его `user_id` в `admins`.
3. Seed-скрипт: `tools-data.js` → база, фото → Storage.
4. Публичные страницы из базы: `/catalog`, `/product/[slug]`, `/generators`, затем остальные. Проверить, что вид совпадает с макетами.
5. Авторизация + middleware на `/admin`.
6. Админка: инструменты → категории → ДГУ → цены → медиа.
7. `revalidatePath` после мутаций.
8. Vercel, домен, `sitemap.ts`, `robots.ts`, метаданные и OG-изображения.
9. Позже — казахская локаль: заполнить `*_kz`, включить `/[locale]/`.
